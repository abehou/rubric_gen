# User-feedback public-evidence firewall: P1/P2

Status: implementation and provider-free tests; no provider calls yet.
The [D×G study](../trace-user-parallel-diagnostics/README.md) is closed: 36/36
feedback checks, 0/27 challenger trajectories. Its private-name leak occurred with
no selected learned reminder. The raw private evaluator channel, rather than
reminder selection alone, is the next hypothesis.

P1: private locator → public-only renderer. P2: private locator → independent
public-only verifier → public-only renderer. Both retain v2.1 separate reminders,
the correct shared selector, and the complete v2.1 learner. No budgeted delivery,
base-slot ranking, label-driven accept rewriting, or extra preservation paragraph.

The locator returns up to three structural candidates in priority order: a closed
issue-type enum, validated public line references, and ordinal priority. It cannot
return prose or arbitrary IDs. Public review receives only the ordinary public
task/artifact/history, issue type and references. Priority and all private feedback
are excluded. P2 additionally passes a public verifier decision/rationale; unsupported
candidates stop, unresolved candidates can only become verification requests or no issue.

Each renderer returns at most one concern. The deterministic union has at most
three concerns and accepts only when none survive. This is the declared pipeline,
not a rewrite based on analytical tags. The v2.1 separate admitted-rule reminder
is still appended by the unchanged common trace delivery path. The firewall only
tests the ordinary simulated-User channel; it is not a claim that arbitrary
learned requirements or previously public history cannot contain bad guidance.

Twelve existing checkpoints, no added fixtures for provider calls. P1/P2 run in
parallel with separate locator samples, two sequential stage streams under the
same global budget. Sharing a selected locator sample is not part of this test.
Per checkpoint: P1 ≤4 logical stages, P2 ≤7, each using the existing Luna settings,
1024 output tokens and at most two native attempts. Valid unfavorable results are
never retried. Paid stages persist immediately and replay without another draw.
The additional compute is part of the method, not compute parity with v2.1.

Every feedback response will be inspected. Reproduced private leakage, false sign
allegations, invalid population contradictions, fabricated public facts, or loss
of useful corrective content blocks that candidate. No winner is selected by
concern count. Only passing candidates may run nine canonical dev3 assignments
against the existing compatible v2.1 control. No Result20, P3, or other arms.
