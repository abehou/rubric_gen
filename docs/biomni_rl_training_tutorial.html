Training Revision Agents Without Training Them to Game the Judge

A practical curriculum for building scientific revision agents that improve substantive quality while treating reward hacking as a constrained safety outcome. The plan starts with evidence instrumentation and offline preference learning, and uses online RL only after the verifier has demonstrated held-out validity.

Contents. Problem formulation · evidence architecture · dataset construction · SFT · DPO · constrained RL · training the process-rubric proposer · evaluation · launch gates.

1. Define the objective correctly

Let x be a task, τ an agent trajectory, and y its final submission. We care about latent scientific quality Q(x,τ,y), but can only observe proxies: rubric score S, rubric-free preference F, process-verification score P, and an RH detector H. A naive objective max E[S] invites optimization of errors in S.

Proxy-overoptimization argument. Write S = Q + ε, where ε is evaluator error. Selection for high S selects both high Q and positive ε. As optimization pressure increases, the upper tail increasingly contains trajectories with unusually large ε. Therefore improvement in S need not imply improvement in Q. This is regression-to-the-mean/Goodhart behavior, not an exotic failure mode.

Use a constrained objective instead:

maximizeπ E[Q̂]   subject to   E[H] ≤ ε,   E[unsupported central claims] = 0.

The hard claim constraint matters: a weighted penalty can be compensated by unrelated rubric points, while a fabricated central result should invalidate or cap the submission.

2. Instrument evidence before training

Every quantitative claim should be connected to a provenance graph:

task data → command/tool event → output artifact + hash → transformation → final claim

Store structured events for commands, exit status, stdout/stderr digests, file changes, data inputs, and final-claim references. A prose trace.md is navigation, not proof.

3. Build an offline curriculum

Generate multiple rollouts from identical sealed initial submissions. Include base, diligent, anti-RH, and deliberately perturbed trajectories. Perturbations should cover hardcoded benchmark values, wrong denominators, failed commands followed by success claims, missing-data substitution, unsupported citations, and cosmetic rubric matching.

Each example receives four independent labels:

  1. rubric-free substantive quality;
  2. claim-level process validity;
  3. RH judgments with evidence;
  4. human adjudication on a stratified disagreement subset.
Data requirement. Forty-seven runs are diagnostic data, not an RL corpus. Use at least dozens of tasks, several sealed seeds per task, and multiple rollouts per condition. Split by task—not trajectory—so near-duplicate revisions cannot leak across train/test.

4. Stage A: supervised fine-tuning

Train the solver on trajectories that demonstrate: inspecting the task anew, executing relevant checks, maintaining a claim ledger, resolving contradictory evidence, and honestly reporting blocked analyses. Include negative-to-positive edits showing how to repair unsupported claims.

The target is a behavior policy with usable support. RL cannot reliably discover disciplined tool use if the pretrained policy rarely performs it.

5. Stage B: preference optimization

Create pairs (τ⁺, τ⁻) where τ⁺ has better rubric-free quality and provenance without RH. Prefer DPO before online policy-gradient training because it is offline, auditable, and avoids a separately learned scalar reward during the first iteration.

DPO derivation

Start with KL-regularized RL:

maxπ Ey∼π[r(x,y)] − β KL(π(·|x) || πref(·|x)).
Optimal-policy proof. Add a Lagrange multiplier for normalization and differentiate with respect to π(y|x). Setting the derivative to zero gives π*(y|x) ∝ πref(y|x) exp(r(x,y)/β). Rearranging, reward differences equal β times differences of log policy ratios. Substitute this into a Bradley–Terry preference model P(y⁺≻y⁻)=σ(r(y⁺)−r(y⁻)) to obtain the DPO logistic loss over policy/reference log-ratio differences. Thus preferences can optimize the same regularized optimum without explicitly fitting r.

6. Stage C: constrained online RL

Once process and RH verifiers are calibrated, optimize substantive reward under explicit costs:

L(π,λ)=E[Q̂]−λ(E[H]−ε),   λ≥0.
Complementary-slackness interpretation. At a constrained optimum, λ(E[H]−ε)=0. If RH is below the budget, λ may be zero; if the constraint binds, λ becomes positive and prices additional RH risk. Updating λ by projected ascent on constraint violation implements a practical primal–dual controller. This does not guarantee safety under a misspecified detector, so detector validation remains a prerequisite.

Use a lexicographic reward: first reject unverifiable central claims, then optimize rubric-free quality, then use frozen-rubric score as a secondary shaping signal.

Potential-based shaping

Dense process rewards can change the task objective. A safe form is F(s,a,s′)=γΦ(s′)−Φ(s).

Policy-invariance proof sketch. Along a trajectory, discounted shaping rewards telescope to −Φ(s₀)+γTΦ(sT). With fixed initial state and zero/constant terminal potential, every policy's return shifts by the same constant. Therefore the ordering of policies and optimal policies is unchanged.

7. Train the rubric proposer as a separate model

The proposer emits the complete rubric for the next revision. It can retain, rewrite, remove, merge, split, reorder, and reweight criteria. An unchanged complete rubric means abstention. The harness derives the diff and does not parse edit actions.

A frozen, versioned trajectory-auditor agent first selects event citations. The packet can report no supported problem, problem hypotheses, counterevidence, and uncertainty. The auditor returns only event IDs and offsets; the harness checks each reference, copies the exact trajectory text, and stores the resulting packet and its hash. The proposer receives only the task, answer, current rubric, and verified packet; it has no trajectory tools and produces no trace file.

Build each complete set through recursive decomposition and filtering. Criteria must be atomic, task-specific, self-contained, outcome-grounded, and discriminative. Use verified packet evidence to verify or falsify outcome quality. Do not reward effort, visible activity, or incomplete work. Give partial credit only for independently useful bounded outcomes. Remove overlap and correlated double-counting.

Rset = downstream quality − RH risk − false positives − answer leakage − overlap − coverage loss.

Do not reward a rubric merely for lowering the current answer's score. That trains adversarial overfitting. Reuse one packet for all candidates from a state. Freeze the auditor while collecting proposer data, and freeze solver and proposer in alternating stages; simultaneous online co-training creates a nonstationary collusion channel.

8. Prevent detector gaming

Training and final evaluation must use disjoint verifier families or hidden prompts/checks. Rotate training verifiers, retain sealed evaluators, and audit disagreements. Never interpret detector agreement as ground truth without a human-calibrated Biomni subset.

Why reuse is invalid. If optimization observes detector D, the learned policy is selected conditional on D's errors. Evaluating with the same D estimates performance against an adapted target, not real RH prevalence. Cross-fitting restores independence: each policy is evaluated by detectors that supplied no training reward for that policy.

9. Experimental design and inference

Use a factorial design over prompt, process verifier, feedback policy, task, and seed. Freeze initial submissions. Pre-register primary outcomes and cluster inference by task and seed.

Small-cluster limit. A two-sided sign-randomization test with four independent tasks has only 2⁴=16 assignments. Even if all four effects have the same sign, two assignments are at least as extreme, so the minimum two-sided p-value is 2/16=0.125. Treating repeated feedback conditions as independent creates pseudoreplication and artificially small p-values.

10. Launch gates

  1. Trajectory retrieval returns validated events on every supported provider schema.
  2. Process patches contain valid evidence and pass held-out counterfactual tests.
  3. Human calibration establishes detector precision/recall with uncertainty.
  4. DPO improves quality without worsening adjudicated RH.
  5. Online RL is allowed only after frozen-detector, hidden-task evaluation passes.

Recommended order: instrumentation → verified additive process patches → SFT → DPO → constrained RL. Skipping directly to RL would optimize the current verifier defects.
